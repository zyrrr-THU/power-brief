# 更新日志

## 2.1.0 — 2026-11-17

### 修复：每天不自动运行
GitHub 的定时任务在高峰期会延迟或被丢掉，11-17 早上 07:30 的定时运行根本没有启动。修改如下：
- 每天改为 4 个时段：北京时间 06:47、07:17、07:47、08:47。先运行成功的那次生成并推送，后面的时段检查到“今天的定时任务已成功”就跳过。网页上手动“更新网页”不算定时运行。
- 运行监控改到 10:47，在最后一个时段之后。
- 首页兜底：北京时间 7 点后最新一期不是今天时，顶部显示提示；已连接 GitHub 的设备可一键“立即生成”；如果定时任务正在运行，直接显示它的进度。

### 提速：手动运行更快、网页自动刷新
- 生成提速：上市公司公告改为 5 个并发查询（原来逐个查）；股价、公告和抓原文同时进行。实测生成从 42–57 秒降到 24 秒（只抓取不写文件的测试运行，未计 AI 解读）。
- 网站发布跳过 Jekyll 构建（新增 `docs/.nojekyll`）。
- 网页进度改为三段（排队 → 生成 → 发布），显示每段用时。发布完成后自动重新下载数据并刷新当前页面，不用再手动点。


## 2.0.0 — 2026-11-16
云端版：GitHub Actions 每天北京时间 07:30 生成简报并发布到 GitHub Pages，任何设备打开网址即看；本机不再需要后台服务和计划任务。
- 设置：网页“设置”页在每台设备“连接 GitHub”一次（只授权本仓库的细粒度令牌，只存在本浏览器）后可修改；修改写入仓库根目录 `settings.json`（只记录与默认值不同的项），程序读取 `config.yaml` 等文件时叠加它（字典逐键合并、列表整体替换、类型不对或文件损坏时忽略）。每个区块可“恢复默认”，可下载 settings.json，修改历史在 Git 里。
- 密钥只在 GitHub Secrets 填写，网页只显示“已配置/未配置”（`docs/data/settings.js` 不含任何密钥内容，有自测保证）。
- 运行页：“更新网页 / 更新并推送到手机”触发云端工作流，显示排队、运行、等待网页发布、完成；最近 14 次运行记录（定时/手动、成功或失败原因、条数、AI 供应商、token、推送结果、运行提示）和日志尾部；连接后还显示 GitHub 上最近的运行。
- 阅读反馈：已连接 GitHub 的设备直接把反馈存入仓库 `state/feedback_inbox/`，不用再开 Issue 页面。
- 云端运行时网页地址和反馈仓库按仓库名自动填写；失败告警附 GitHub 运行链接。
- 工作流：手动运行可选是否推送（默认只更新网页）；生成失败也提交运行记录；提交前先合并网页刚保存的设置，失败重试 3 次；日志保留 7 天。
- 默认配置：`run.mode: github`、AI 供应商 DeepSeek → Claude API、用量口径按 API 实际费用（显示美元和人民币）、`publish.target: github_pages`。
- 修正：直接打开 `#/settings` 等网址时显示成“今日”；快速切换页面时旧页面的数据晚到会盖掉新页面。
- 删除本机专用文件：`powerbrief/server.py`、`PowerBrief.bat`、`create_shortcut.*`、`install_task.*`、`uninstall_task.bat`、`run_daily.bat`、`docs/admin.js`（由 `docs/manage.js` 取代）；`config.yaml` 删除 `app.window`。本机的计划任务 PowerBrief、PowerBrief-Check 和后台服务已停止并删除。
